# DECISIONS.md — журнал архитектурных решений QuikLight

> Короткие ADR: что решили, почему и в каком статусе. Актуальное состояние кода —
> в `docs/ARCHITECTURE.md`, протокол — в `docs/PROTOCOL.md`.
> Формат даты — ISO (`YYYY-MM-DD`).

## ADR-001 — Rust + AppKit (`objc2`) + `hidapi`, Cargo workspace

**Дата:** 2026-08-14
**Статус:** принято, реализовано

Свой native menu bar app вместо официального Electron-приложения SyncLight.
Rust даёт перенос протокола и цветообработки из SyncRGB почти 1-в-1, нулевой
рантайм и целевой вес 10–40 МБ RAM. GUI — AppKit через `objc2`, без Xcode-проекта.
HID — крейт `hidapi` (тот же, что в SyncRGB). Сборка — Cargo workspace + скрипт
`.app`-бандла.

**Отклонено:** Swift/SwiftUI (нужен полноценный Xcode), Electron/Tauri/Flutter
(тяжёлые), Python + PyObjC (слаб для 30–50 fps).

## ADR-002 — Только USB-вариант панели

**Дата:** 2026-08-14
**Статус:** принято

У владельца панель `1A86:FE07` по USB, interface 0 — канал управления.
BLE/донгл-вариант использует другой протокол (MAC-адресация, 20-байтные кадры,
модуль `62564` в SyncLight) и в проект не входит.

## ADR-003 — Захват экрана через `SCScreenshotManager`, а не `SCStream`

**Дата:** 2026-08-14
**Статус:** принято, реализовано

Периодический захват `CGImage` проще и надёжнее в `objc2`, чем поток `SCStream`.
Цена — требование macOS 14+ для screen sync; статичные режимы и эффекты
работают на macOS 13+.

## ADR-004 — Число LED и раскладка из `readDeviceInfo`

**Дата:** 2026-08-14
**Статус:** принято, реализовано

Число LED не хардкодится: приходит из `readDeviceInfo` (action 130). У панели
владельца 51 LED (24", прошивка 1.8.2), авто-раскладка — 17/29/17.
`DEFAULT_LED_COUNT = 63` — фолбэк, если устройство ещё не ответило.

## ADR-005 — Один фоновый поток-движок и `mpsc`

**Дата:** 2026-08-14
**Статус:** принято, реализовано

HID-устройством владеет единственный поток `engine`; UI общается с ним через
`std::sync::mpsc` (`Command` →, `WorkerEvent` ←) и опрашивает события таймером
0.25 с. Запись сериализуется через `&mut Device` — чанки одного кадра не
перемежаются. UI никогда не блокируется на HID.

## ADR-006 — Обновление из публичных GitHub Releases своим updater-ом

**Дата:** 2026-11-24
**Статус:** принято, реализовано

Проверка обновлений — вручную (пункт меню «Проверить обновление…»). Манифест
`latest.json` лежит ассетом последнего релиза
(`releases/latest/download/latest.json`) и содержит только строки: `version`,
`url`, `sha256`, `min_macos`. Перед установкой проверяются SHA-256 архива,
подпись `codesign`, `CFBundleIdentifier` и версия в `Info.plist`; бандл
подменяется helper-скриптом после выхода приложения, с откатом при ошибке.
Релиз публикует `scripts/release.sh` (сборка, zip через `ditto`, тег, `gh release`).

**Отклонено:** Sparkle (своя подпись и нотаризация, лишний фреймворк), GitHub API
(лимиты запросов и разбор вложенного JSON), схема «приватный репозиторий +
токен в приложении» (секрет в бинарнике).

## ADR-007 — Сеть и распаковка штатными утилитами macOS

**Дата:** 2026-11-24
**Статус:** принято, реализовано

Updater работает через подпроцессы `curl`, `ditto`, `codesign`, `shasum`,
`plutil` и `sw_vers`; JSON разбирается `NSJSONSerialization` (уже доступен через
`objc2-foundation`). Никаких сетевых крейтов и `serde` не добавлено: ноль новых
зависимостей, поведение совпадает с ручной установкой релиза.

**Компромисс:** такой updater применим только к macOS (приложение и так
macOS-only) и требует, чтобы утилиты лежали по стандартным путям.

## Открытые вопросы

| Вопрос | Текущее состояние |
|---|---|
| Персистентность настроек | Не реализована: `Settings` живёт в памяти (`Copy`), файла нет |
| Автозапуск (`SMAppService`) | Не реализован |
| Автообновление | Проверка только вручную; авто-проверка при запуске не сделана |
| Sound reactive (звук ПК) | Вне скоупа; встроенные звуковые эффекты панели (tipo 3) работают без ПО |
| dmg и нотаризация | Не реализованы: релиз — `.zip` с `.app`, подпись самоподписанным сертификатом; обновление доступно только при публичном репозитории |
