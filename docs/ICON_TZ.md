# ТЗ на генерацию иконок QuikLight

Версия: 1.1
Дата: 2026-08-14 (обновлено 2026-09-30)
Статус: **выполнено** — иконки лежат в `assets/icons/`, упаковка в бандл — в `scripts/build_app.sh`

## 1. Цель

Сгенерировать два визуальных артефакта для macOS-приложения **QuikLight** —
нативного menu bar приложения, управляющего LED-панелью Robobloq QuikLight
(амбиентная подсветка краёв монитора, screen sync, эффекты):

1. **App icon** — иконка приложения (Dock / Finder / Launchpad / Spotlight).
   Сейчас отсутствует полностью: в бандле пустой `Contents/Resources`,
   в `Info.plist` нет ключа `CFBundleIconFile`.
2. **Menu bar icon** — иконка в системном меню (верхняя строка macOS).
   Сейчас вместо неё текстовый глиф `○` / `◉` (`crates/quiklight-app/src/main.rs`).

## 2. Контекст и бренд

- Приложение — «тонкий» аналог официального SyncLight: лёгкое, быстрое,
  нативное. Ассоциации: свет, LED-лента, свечение за монитором, ambilight,
  тёплый огонь (фирменный эффект «Камин»), прохладные тона screen sync.
- Никакого текста и букв на иконках **не должно быть** (в т.ч. логотип
  «QuikLight» — не рисуем).
- Стиль: современный macOS (Big Sur+), мягкие градиенты, лёгкое свечение,
  минимализм, узнаваемость на маленьких размерах.

## 3. Артефакт 1 — App icon (1024×1024, полноцветная)

### 3.1 Концепт (рекомендуемый)

Тёмный экран монитора (вид спереди, крупно, по центру) с **светящейся
LED-полосой за его краями** — классический ambilight-образ:

- по бокам и сверху монитора — яркая LED-полоса, «просвечивающая» из-за
  корпуса;
- свет от ленты мягко заливает фон (glow / bloom);
- сам монитор почти чёрный (тёмно-графитовый), чтобы свет выглядел ярко;
- тон акцентов: **тёплый оранжево-янтарный** (эффект «Камин») слева/снизу +
  **холодный сине-фиолетовый** (screen sync) справа/сверху — тёплый и
  холодный свет вместе, как у настоящего ambilight;
- форма корпуса монитора может слегка напоминать LED-панель QuikLight
  (вытянутый прямоугольник), но без текста и без попытки нарисовать
  точное устройство — важна идея «свет за экраном».

Альтернативы (если рекомендованный не нравится):

- **A2. Светящаяся лента сама по себе** — изогнутая LED-полоса (дуга / углы
  монитора), на тёмном фоне, с точками-светодиодами и градиентным свечением.
- **A3. Огонь/пламя** — минималистичное пламя из точек LED (акцент на
  эффекте «Камин»), тёплые тона, фон градиент чёрный→тёмно-бордовый.

### 3.2 Технические требования (обязательно)

| Параметр | Значение |
|---|---|
| Размер полотна | 1024×1024 px (квадрат) |
| Цветовое пространство | sRGB |
| Формат на выходе | PNG, альфа-канал (RGBA), без сжатия артефактов |
| Скругление углов | **НЕ скруглять** — macOS сам наложит маску (squircle). Иконка — полный квадрат с рисунком «в край» |
| Безопасная зона | Ключевые элементы (монитор, лента) — в центральном квадрате ~824×824 px (маржа ~100 px по краям); мягкое свечение/glow может выходить за неё |
| Радиус скругления маски | ~185 px от угла 1024-х (примерно 22.5%) — для проверки «впишется ли» |
| Стиль | macOS Big Sur+: градиентный фон, объём, мягкие тени, glow |
| Запрещено | текст/буквы/логотип; фото; мелкие детали, нечитаемые на 128 px; грязный фон (сетки, водяные знаки) |

### 3.3 Чек-лист читаемости

При проверке уменьшенной копии иконка должна оставаться узнаваемой:

- 512 px — видна идея «монитор + свет за краями»;
- 128 px (Finder/Launchpad) — читается силуэт монитора и яркая лента;
- 32 px — читается хотя бы как «светящийся контур экрана».

### 3.4 Промпт (можно вставлять в генератор как есть)

> macOS app icon, 1024×1024, square canvas, no rounded corners, no text.
> Dark monitor screen viewed from the front, centered, almost black
> graphite display. A bright RGB LED strip glows from behind the monitor
> edges — warm amber-orange on the left and bottom, cool blue-violet on
> the right and top, like ambilight backlight. Soft glowing bloom spills
> onto a dark background. Modern minimal macOS Big Sur style, smooth
> gradients, subtle glow, premium look. No text, no letters, no logo,
> no watermark. High detail at 1024 px, still readable at 128 px.

## 4. Артефакт 2 — Menu bar icon (монохромный template)

### 4.1 Назначение и поведение

Заменяет текущий текстовый глиф `○`/`◉` в верхнем меню macOS. macOS сам
перекрашивает иконку под светлую/тёмную тему, поэтому иконка обязана быть
**template image**: чёрная + альфа, без белого и без градиентов.

### 4.2 Концепт

Максимально простой силуэт из app icon — **«светящаяся LED-полоса по углам
монитора»**:

- тонкая полоса/дуга по трём сторонам (или два угла — верхний правый +
  нижний левый) — намёк на ambilight;
- без деталей, без градиента — только заливка чёрным с плавным
  прозрачным «затуханием» концов ленты (а если совсем просто — чистый
  контур, читаемый на 16 px);
- в выключенном состоянии приложение может подменять её на «погасшую»
  версию (та же форма, но с «разрывом»/тусклее) — по желанию;
  минимально для ТЗ: одна основная форма.

Силуэт должен читаться **одним пятном** на 16 px: никаких зазоров тоньше
1 px и элементов мельче 2 px.

### 4.3 Технические требования (обязательно)

| Параметр | Значение |
|---|---|
| Тип | Template image: **только чёрный (#000000) + альфа**. Никакого белого, серого, цвета |
| Сетки | 16 pt (старые macOS) и 18 pt (macOS 11+), каждая в @1x / @2x / @3x |
| Файлы | `menubar@1x.png` (16×16), `menubar@2x.png` (32×32), `menubar@3x.png` (48×48); дополнительно 18 pt: `menubar18@1x.png` (18×18), `menubar18@2x.png` (36×36), `menubar18@3x.png` (54×54) |
| Отступ | Внутри кадра — паддинг ~1–2 px от краёв; визуальный центр чуть выше геометрического |
| Антиалиасинг | Мягкий, стандартный; края без «грязи» |
| Запрещено | градиенты, тени, цвет, белые пиксели, растр с «мусором» от генератора |

### 4.4 Важно про способ генерации

AI-генераторы почти всегда выдают «грязный» растр для такого мелкого
монохрома. Рекомендуемый порядок:

1. Из app icon выделить ключевую геометрию (полосу света по углам).
2. Перерисовать **вручную** (Figma / Illustrator / Inkscape / вектор в
   коде) — это 2–3 фигуры, 15 минут.
3. Экспортировать PNG-сетки из п. 4.3 и прогнать через постобработку:
   перевести всё в чёрный, оставить только альфу (если инструмент это
   умеет — «threshold» по альфе), проверить на белом и чёрном фоне.

Если всё же генерировать: генерировать не 16 px, а 512 px чёрно-белый
силуэт, затем вручную свести к шаблону.

## 5. Палитра (для app icon)

| Роль | Цвет |
|---|---|
| Фон (тёмный) | #0A0A0C → #1A1A1F (градиент) |
| Экран монитора | #121216 с бликом #2A2A33 |
| Тёплый свет (Камин) | #FF7A18 → #FFC24B (градиент, glow) |
| Холодный свет (screen sync) | #4C7CFF → #9B6CFF |
| Корпус/тени | #000000 → #26262E |
| Блики на LED | #FFFFFF (точечно, маленькие капли) |

Допускается смещение оттенков, если сохраняется контраст «тёплое vs
холодное свечение на почти чёрном».

## 7. Как файлы будут использованы в проекте (для справки)

- `AppIcon.icns` кладётся в `Contents/Resources/` бандла, в `Info.plist`
  добавляется `CFBundleIconFile = AppIcon` (обновляется
  `scripts/build_app.sh`; сборка `iconutil` из PNG-набора).
- PNG меню-бара кладутся в `Contents/Resources/`, в коде загружаются в
  `NSImage` с `image.setTemplate(true)` вместо `button.setTitle("○")`.
- До появления файлов приложение продолжает работать со старым глифом —
  интеграция не блокирует генерацию.
