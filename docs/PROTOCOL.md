# PROTOCOL.md — Протокол управления Robobloq QuikLight (USB-версия)

> Документация получена независимым reverse engineering официального приложения **SyncLight 2.19.1** (Electron: протокол лежит в `resources/app.asar` → `.webpack/main/index.js`, модули `5786` транспорт, `60895` протокол USB-ленты) и подтверждена тремя открытыми реализациями. Верифицировано байт-в-байт против официального приложения.
>
> Версия документа: **1.2** (2026-11-24). Проверено на панели 24" (реально 51 LED) с прошивкой **1.8.2**.

## Идентификация устройства

| Поле | Значение |
|---|---|
| Vendor ID | `0x1A86` (QinHeng Electronics / WCH) |
| Product ID | `0xFE07` |
| Manufacturer | `ROBOBLOQ` |
| Product | `USBHID` |
| Interface 0 | HID generic, endpoints 64 байта — **канал управления** |
| Interface 1 | HID keyboard — сенсорные кнопки панели |

⚠️ **Критично:** interface 1 выглядит как второе HID-устройство и **игнорирует** команды цвета. Ошибка выбора интерфейса даёт тишину, а не ошибку. Всегда открывай **interface 0**.

## Формат кадра (RB)

```
┌─────┬─────┬─────────┬──────┬───────┬──────────┬──────────┐
│ 'R' │ 'B' │ size(1) │  id  │ action│ payload  │ checksum │
└─────┴─────┴─────────┴──────┴───────┴──────────┴──────────┘
  0     1       2       3      4      5..n-2      n-1
```

- `'R'` = `0x52`, `'B'` = `0x42`
- **size**: полный размер кадра в байтах (включая заголовок и checksum). Один байт → кадр ≤ 255 байт
- **id**: счётчик сессии, монотонно растёт, после 255 возвращается к 1 (в оригинале стартует с 2). Служит для сопоставления ответа с запросом
- **action**: код операции (таблица ниже)
- **checksum**: сумма всех предыдущих байт кадра по модулю 256 (wrapping)

## Формат кадра (SC) — screen sync

Используется только для передачи цветов экрана (action `128`):

```
┌─────┬─────┬──────────┬──────┬───────┬──────────────┬──────────┐
│ 'S' │ 'C' │ size(2 BE)│  id  │ action│  colors...   │ checksum │
└─────┴─────┴──────────┴──────┴───────┴──────────────┴──────────┘
  0     1      2-3       4      5      6..n-2          n-1
```

- `'S'` = `0x53`, `'C'` = `0x43`
- **size**: 2 байта, big-endian, полный размер кадра
- payload — массив цветов `[R,G,B, R,G,B, ...]` (по 3 байта на LED)

## Передача по HID

- Каждый HID-отчёт начинается с **report ID `0x00`** + данные
- Кадры > 64 байт режутся на чанки по 64 байта, **каждый чанк — со своим report ID**
- Команды с ожиданием ответа (read/write): писать, подождать **~200 мс**, читать с таймаутом **500 мс**
- Команды без ответа (screen sync, rhythm): писать без ожидания
- Писать строго последовательно (очередь) — чанки одного кадра не должны перемежаться чужими

## Цвет — действие 134 (setSectionLED)

Payload — последовательность групп по 5 байт:

```
[ led_начало, R, G, B, led_конец ]
```

- LED нумеруются **с 1**
- `254` = «до конца ленты» (не зависит от фактического числа LED) — поэтому «погасить всё» = `[1, 0, 0, 0, 254]`
- Несколько групп в одном кадре → можно нарисовать градиент одной записью. Лимит: кадр ≤ 255 байт → до 49 групп
- Пример: вся лента красным = `[1, 255, 0, 0, 254]`
- Пример: первые 20 LED синим, остальные выкл = `[1, 0, 0, 255, 20, 21, 0, 0, 0, 254]`

## Ответ readDeviceInfo (action 130)

Ответ — RB-кадр. Расположение полей — **смещения от начала кадра** (0-based, от байта `'R'`; payload начинается с offset 5). Таблица сверена с оригиналом quicklight-linux PROTOCOL.md и проверена на реальном железе (прошивка 1.8.2):

| Смещение (от начала кадра) | Содержимое |
|---:|---|
| 5–7 | id устройства |
| 8 | настроенный размер экрана |
| 11 | число LED |
| 12–19 | uuid |
| 21–23 | версия прошивки (major, minor, patch) |

(При парсинге допускай несовпадение длины и логируй сырые байты.)

> У панели владельца (24", прошивка 1.8.2) — 51 LED и авто-раскладка 17/29/17.
> Для другой панели число LED узнаётся через `hidprobe info`. Пока устройство
> не ответило, приложение использует фолбэк `DEFAULT_LED_COUNT = 63`.

## Эффекты — действие 133 (setLedEffect)

Официальный интерфейс: два типа, по 7 эффектов в каждом:

- **tipo 2** — динамические эффекты (радуга, поток, дыхание…), индексы 0–6
- **tipo 3** — реакция на звук, индексы 0–6

Важно для типа 3: официальное приложение различает **ритм компьютера** (приложение само захватывает аудио ПК и шлёт цвета кадр за кадром — это action 152 `setComputerRhythm`) и **ритм контроллера** (панель использует собственный микрофон; включается простой отправкой action 133 — работает вообще без ПО). Если звуковая реакция не нужна в ПО — достаточно 133.

## Подводные камни (из реверса официального приложения)

1. **Скорость эффектов инвертирована**: слайдер в UI → на устройство уходит `setDynamicSpeed(100 - slider)`.
2. **Старые прошивки (< 1.8.0) не знают action 151** (turnOffLight). Официальное приложение гасит рисованием всего чёрным `[1,0,0,0,254]`. Делай оба способа: сначала 0x97, при отсутствии эффекта/для совместимости — чёрный цвет.
3. **При выключении приложение повторяет команду 4 раза с интервалом 20 мс** — панель иногда теряет записи.
4. **Авторизация отсутствует.** HMAC-SHA256 verify существует только для клавиатур/мышей Robobloq, лента его не требует.
5. **Скорость официального screen sync**: захват 20 мс (50 fps), задержка отправки `syncSpeed + 20 мс`. Для нас достаточно 30–50 fps.
6. **`setBrightness` принимает 0..100**: панель понимает 0 (гасит) и 100 (максимум). Ограничение `max(5)` в SyncRGB — это минимум UI-слайдера, а не требование протокола.

## Эталонные hex-пакеты (для юнит-тестов)

Все примеры — id сессии = 2; `checksum = сумма всех байтов кадра (кроме самого
checksum) mod 256`. Значения сверены с `cargo test` (`protocol/packet.rs`,
`protocol/actions.rs`): в ранних референсных документах часть checksum была
указана неверно — ниже приведены корректные.

| Команда | Кадр |
|---|---|
| Яркость 50 (action 135) | `52 42 07 02 87 32 56` |
| Выключить (action 151) | `52 42 06 02 97 33` |
| Вся лента красным (action 134, payload `[1,255,0,0,254]`) | `52 42 0B 02 86 01 FF 00 00 FE 25` |
| Всё чёрным (action 134, payload `[1,0,0,0,254]`) | `52 42 0B 02 86 01 00 00 00 FE 26` |
| Инфо устройства (action 130) | `52 42 06 02 82 1E` |

Для action 130 `size` = полный размер кадра: `'R' 'B' + size + id + action + payload(0) + checksum` = 6 байт.

> ⚠️ **Важно для тестов:** hex-примеры пересчитаны программно и продублированы
> юнит-тестами. Если расхождение — сначала проверь свой код: формула простая и
> подтверждена тремя независимыми реализациями.

## Схема записи HID (пример для яркости 50)

```
Отчёт: 00 52 42 07 02 87 32 56
       ^ report ID 0x00
```

Чанкинг >64 байт: например, SC-кадр на 65 LED = 2+2+1+1+195+1 = 202 байта → 4 отчёта по 64 байта (последний 10 байт), каждый с report ID 0x00.
